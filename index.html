Part 1: Ray Generation and Scene Intersection

Ray Generation and Primitive Intersection Pipeline

The rendering pipeline starts with ray generation, where, for each pixel, we sample ns_aa points within the pixel, transform them into world coordinates, and construct rays originating from the camera position. This is implemented in the raytrace_pixel

Next, we determine which object each ray intersects. We test the rays against scene primitives, such as triangles and spheres, and select the closest valid intersection along each ray. We then record the intersection information, including the surface normal, which is used for normal shading.

Triangle Intersection Algorithm

To find the intersection point between a ray \(\mathbf{r}(t)=\mathbf{o}+t\mathbf{d}\) and a triangle with vertices \(\mathbf{v}_1,\mathbf{v}_2,\mathbf{v}_3\in\mathbb{R}^3\), recall that every point in the triangle can be expressed using barycentric coordinates:

\[ \mathbf{p}=(1-b_2-b_3)\mathbf{v}_1+b_2\mathbf{v}_2+b_3\mathbf{v}_3 =\mathbf{v}_1+b_2(\mathbf{v}_2-\mathbf{v}_1)+b_3(\mathbf{v}_3-\mathbf{v}_1) \]

We seek a \(t\) such that

\[ \mathbf{r}(t)=\mathbf{v}_1+b_2(\mathbf{v}_2-\mathbf{v}_1)+b_3(\mathbf{v}_3-\mathbf{v}_1) \]

This is equivalent to solving the linear system

\[ \begin{bmatrix} \vert & \vert & \vert\\ \mathbf{d} & \mathbf{v}_1-\mathbf{v}_2 & \mathbf{v}_1-\mathbf{v}_3\\ \vert & \vert & \vert \end{bmatrix} \begin{bmatrix} t\\ b_2\\ b_3 \end{bmatrix} = \mathbf{v}_1-\mathbf{o} \]

A valid ray-triangle intersection must satisfy

\[ t\in [\texttt{t\_min}, \texttt{t\_max}],\qquad b_2\geq 0,\qquad b_3\geq 0,\qquad b_2+b_3\leq 1. \]

If these conditions hold, the intersection point is \(\mathbf{p}=\mathbf{o}+t\mathbf{d}\). Hence, to compute the intersection, we solve the above linear system, and then check whether the solutions \((t, b_2, b_3)\) satisfy the constraints.

Part 2: Bounding Volume Hierarchy

Construction of Bounding Volume Hierarchy

We construct the BVH recursively using the following algorithm:

  1. Compute the bounding box enclosing all primitives in the current group.
  2. We create a new node.
  3. Create a new BVH node containing this bounding box.
  4. If the number of primitives is less than or equal to the maximum allowed leaf size, create a leaf node and stop recursion.
  5. Otherwise, select the longest axis of the bounding box as the splitting axis.
  6. Sort the primitives by their centroids along the selected axis, and split them into two groups at the median.
  7. Recursively construct the left and right subtrees using the two groups.

The splitting heuristic is the median of the primitives' centroids. This produces two groups with approximately equal numbers of primitives, which helps maintaining a balanced BVH tree and reducing the number of intersection tests during traversal.

Part 3: Direct Illumination

Implementation of Direct Illumination

We implement the estimate_direct_lighting_hemisphere as follows:

  1. Compute the outgoing direction \(\omega_{out}\) pointing toward the ray's origin (already implemented).
  2. Iterate num_samples times, sampling an incoming direction \(\omega_{in}\) using hemisphereSampler.
  3. Construct a ray from the current surface point in direction \(\omega_{in}\) (need to convert to world coordinates). If it intersects an emissive surface, set \(L_i\) to its emission; otherwise, \(L_i=0\).
  4. Evaluate the BSDF \(f_r\) and accumulate the outgoing radiance: \[ L_{out} \mathrel{+}= f_r(\omega_{out},\omega_{in})L_i\cos\theta \]
  5. Finally, multiply \(L_{out}\) by \(\frac{2\pi}{\texttt{num\_samples}}\) to account for the uniform hemisphere sampling PDF.

The importance sampling implementation is similar, except that instead of uniformly sampling directions over the hemisphere, we sample directly from the light sources.

  1. Iterate over all lights in the scene. For each light, take one sample if it is a delta light; otherwise, take ns_area_light samples.
  2. Use sample_L to sample an incoming direction \(\omega_{in}\), the incoming radiance \(L_i\), the distance to the light, and the sampling PDF.
  3. Construct a ray toward the light. If no primitive blocks the ray before it reaches the light, accumulate \[ L_{out} \mathrel{+}= \frac{f_r(\omega_{out},\omega_{in})L_i\cos\theta} {\mathrm{pdf}(\omega_{in})} \]
  4. Average the contributions over the samples for each light and sum the results across all lights.

The importance sampling version allows point light sources since we now sample from the light sources directly.

Below shows examples with hemisphere and importance sampling. As can be seen, hemisphere sampling often results in high variance and visible noise. Part 4: Global Illumination

Implementation of Indirect Illumination

We reuse the one_bounce_radiance in Part 3 as follows

  1. If the remaining ray depth is 0, return L_out directly.
  2. If isAccumBounces is enabled or the remaining depth is 1, add the direct lighting contribution using the implemented one_bounce_radiance from part 3.
  3. If the remaining depth is 1, return L_out since no further bounces are allowed.
  4. Apply Russian roulette with continuation probability of \(p=0.6\), except at the maximum depth, where \(p=1\). This guarantee the first indirect bounce.
  5. If the ray survives, we sample a new direction from the BSDF and construct a new ray with its remaining depth decreased by one.
  6. If the new ray intersects another primitive, recursively compute the incoming radiance and accumulate its contribution as: \[ \frac{f(\omega_o,\omega_i)L_{\text{incoming}}|\cos\theta_i|} {p\,\mathrm{pdf}(\omega_i)}. \] Here, \(L_{\text{incoming}}\) is the radiance returned by the recursive call to at_least_one_bounce_radiance. This represents the light arriving from the sampled direction after subsequent bounces.

Part 5: Adaptive Sampling

Implementation of Adaptive Sampling

In Task 4, we estimate each pixel's color using Monte Carlo sampling:

\[ \hat{L}=\frac{1}{n}\sum_{i=1}^n L_i \]

However, different pixels may require different numbers of samples to converge. For example, smooth surfaces or uniformly lit areas (i.e., low-variance regions) may require fewer samples to obtain a reasonably accurate estimate. In contrast, high-variance regions may require more samples to reduce noise. Adaptive sampling allows us to dynamically adjust the number of samples used for each pixel.

In particular, after collecting a batch of samplesPerBatch samples, we compute the sample mean \(\mu\) and standard deviation \(\sigma\) of the luminance values. We then check whether the \(95\%\) confidence interval half-width satisfies

\[ I=1.96\frac{\sigma}{\sqrt{N}}\leq \texttt{max\_tolerance}\cdot\mu \]

where \(N\) is the total number of samples collected for the pixel. If this condition is satisfied, we stop sampling that pixel. Therefore, pixels with smaller variance have smaller \(\sigma\) and generally require fewer samples to satisfy the termination criterion.

In terms of implementation, we keep track of the running first and second moments of the sample luminance values, which allow us to compute the sample mean and standard deviation without storing all previous samples.
